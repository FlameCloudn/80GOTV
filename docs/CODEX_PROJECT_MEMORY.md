## 产品定位

- 80GOTV 是中文 Counter-Strike 2 赛事与数据网站。
- 现有主要页面：新闻、比赛、赛果、赛事、选手、数据、预测、数据看板、论坛和游戏。
- 只展示网站真正拥有的数据与功能，不为了模仿其他网站而添加空内容。
- 已删除网站标签功能，不要重新加入。

## 视觉规则

- 视觉参考以实际打开并截图后的 HLTV 为准，不凭印象修改。
- 借鉴 HLTV 的紧凑信息密度、边框、表格和移动端结构，但保留 80GOTV 现有配色与整体性。
- 桌面端导航与内容主栏目标宽度为 1200px，各页面主栏宽度保持一致，不挤压也不过度拉长。
- 网站外侧使用网站自身背景色，不使用黑边或突兀外框。
- 移动端不是另做一套产品：内容和桌面主页一致，只做紧凑重排；不可横向溢出、遮挡或出现神秘黑框。
- 移动端顶栏保留品牌和主要入口，更多内容放进覆盖式侧栏；侧栏外背景变灰且不可交互。
- 移动端主页不显示排行、赛事侧栏和选手侧栏。
- 选手目录桌面端一行 5 张卡片，移动端一行 2 张。
- 选手卡片信息顺序：选手名称、群内昵称、注册日期；没有群内昵称时不显示空文字。
- 深浅色切换控件大小保持一致；顶部图标不要变成 emoji。
- 后台不用专门适配移动端，但后台各页面视觉风格必须统一。

## 账号与权限

- 访客可以浏览公开内容，但不能编辑或使用需要账号的站内操作。
- 注册属于选手申请：需要邮箱、Steam 身份验证和管理员审核，不是无条件访客注册。
- `group_username` 表示群内昵称，是必填信息，不是真实姓名。
- 老账号若群内昵称为空，登录后必须先进入个人资料填写；完成前其他受保护操作应被拦截。
- 页面优先显示群内昵称；网站账号可以作为 `@账号` 辅助显示。不要公开或回退显示真实姓名字段。
- 管理员可以管理队伍、队员和队长；队长可以改队名、上传队标、移除队员和解散自己的队伍。
- 个人报名入口按既定日期开放，开放前不显示。

## 数据与业务约定

- 站内比赛 Rating 使用 `RATING 2.0`。
- 赛事 URL 使用可选 slug；比赛 URL 使用“赛事-队伍-日期”格式。
- 赛事创建时 B 站 URL 不是必填项。
- 评论编号 `#xx` 表示整页回复楼数。
- 队伍名形如 `Team Xxx` 时，默认缩写采用 `TX` 形式。
- 选手表现优先从数据库汇总表读取，避免每次请求临时解析 Demo。

## 本地测试

- 常用完整测试命令：`python -m pytest tests -q -p no:cacheprovider`。
- 页面视觉改动必须用真实浏览器分别检查桌面端和移动端截图。
- 移动端重点检查：`document.documentElement.scrollWidth` 不得大于 `clientWidth`。
- 本地测试服务通常使用 `http://127.0.0.1:5005`，完成后关闭本轮启动的测试进程。
- 视觉截图统一放在 `output/ui-audit/`。

## 公网部署

- 公网地址：`https://80gotv.cn`。
- 服务器应用目录：`/srv/80gotv/app`。
- 线上备份目录：`/srv/80gotv/backups`。
- 网站服务：`80gotv-web`；数据直播后台：`80gotv-live`；前置服务为 Nginx，HTTPS 由 Certbot 自动续期。
- 每次部署顺序：本地完整测试 -> 打发布包 -> 上传 -> 线上文件备份 -> 解压与语法检查 -> 重启服务 -> 检查 `/healthz` 和目标页面。
- 服务器内部直接检查 Gunicorn 时必须带 `Host: 80gotv.cn`，否则可信域名保护会拒绝 `127.0.0.1`，形成自检假警报。
- 自动备份定时器：`80gotv-backup-daily.timer` 和 `80gotv-backup-full.timer`。
- 不在文档或脚本中保存登录密码；密码只应从安全环境变量或交互输入提供。

## 安全底线

- 所有写操作接口保留登录、权限和 CSRF 检查。
