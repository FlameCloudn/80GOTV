# 实施路线

| 工作流 | 可并行的交付 | 合并门槛 |
|---|---|---|
| 数据与任务基础 | 提取实际的连接/事务所有者，在开发与独立 worker 同用正式任务，不另加调度服务 | 旧导入、外键、外层撤销、建库/升级；后台停止能收尾 |
| 竞猜与赛务 | 合并旧/托管写票、结算、读榜；保留比赛详情、旧投票及公开榜 | 旧结果更正和托管 BO3、技术重赛、撤销、晋级不分开提交 |
| 社区互动 | 让评论、论坛回复及通知有明确写入口；仍区分不同目标和访问范围 | 原提交、回复、删除、计数、通知；另一账号不能读取或处理他人私信箱 |
| 荣誉与历史榜 | 荣誉模块按正式决赛授冠军、凭实际出场办理本届 MVP/EVP，并维护历史奖与年度人工榜；页面、海报、API 消费已授事实 | 重存不改原颁奖日期、个人奖不自动授给 Rating 最高者、俱乐部不是历史出场依据 |
| 目录、搜索与内容 | 同一实体共用公开搜索条件，保留全文页与快速提示差别；保留原链接和私有覆盖 | 浏览器及 JSON 对照，外部链接、昵称、无结果与可见性 |
| 游戏、身份、统计与存储 | 沿真实重复规则推进，不为了目录整齐改已验证的题库、解析器或存储格式 | 各自原工作流、统计样本、旧/新数据及完整备份恢复样例 |
| 集成 | 汇总模块定向测试、本地全套 Python、页面与老导播合同；将遗留基线单列 | 实际通过和未通过分别记入 [进度](PROGRESS.md)，不以“做过设计”代替 |

前端实现由站主另行负责。真实客户端比赛彩排、真实历史数据迁移演练、生产迁移、部署和推送不等同于本地重构，不自动执行。

## 将来发布前

1. 从明确选入的代码生成候选版本，清点本地尚未跟踪的运行模块、测试装置和必要资源。不能把现有工作树原样当成可发布版本，也不能只打包已提交部分就假定东西齐了。
2. 在候选环境安装[测试依赖](../../requirements-test.txt)和根目录的 Node 开发依赖，用 `npm test` 做全套检查。GitHub 配置已对齐，原生产更新脚本仍用 unittest；候选环境的检查方式与正式发布分别确认。
3. 在截止、赛果改判、原导播收发和备份恢复上核对真实历史副本及现场设备。生产迁移、发布和推送都另行授权。
