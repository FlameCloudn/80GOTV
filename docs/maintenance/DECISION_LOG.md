# 架构决策

| 决定 | 依据及影响 |
|---|---|
| 保留现有运行栈和 HTTP 合同 | 原 Flask 已能承载新赛务，风险集中在同一数据有多个写入口；不花一次全站迁移的代价更换框架。 |
| 统一入口，不统一不相同的语义 | 正式比赛图数不等于实际开局数；年度人工 Top 10 不等于实时 Rating 前十；比赛评论与论坛回帖共表也不必共用所有规则。 |
| 兼容按实际调用者而定 | 保留导播回执、选图下标、历史链接、非公开下载、网页登录和后台行为；不把模板字段直接改成目标表列名。 |
| 共用业务事务，不把一次操作拆给多个数据库连接 | 结果改判、下游绑定和竞猜撤旧计新必须一起生效；发回复失败不能只留下通知。独立操作不强塞一个大事务。 |
| 回归先看工作区基线 | 开始时本地 `main` 比已记录的跟踪分支领先 1 个提交，另有已修改和未跟踪的赛务、界面、文档。保留所有既有工作，不把历史脏差异当成本轮交付。 |
| 前端移交站主 | 本轮不修改模板、样式、脚本、词典或导播应用。验证旧页面能消费后端结果不等于替站主验收界面。 |
| 站主批准本机 SQLite v6；不回填历史冠军 | 旧冠军必须填长期俱乐部号。新增两张只在明确授奖时写的表，比伪造俱乐部或重写既有冠军更符合事实。只取正常冠军决赛的正式选局与五人出场，异常个案不自动判。版本 3/4/5 的本机升级共用原事务。 |
| 托管赛事个人奖复用旧勋章表 | 赛事级 MVP/EVP 已有存放位置，不需要第三张新表。管理员从有正式出场依据的人中选择；个人奖、团队冠军、实时 Rating 互不触发。已授的单场奖不会因编辑赛事奖被删掉。 |
| 只在测试环境补齐工具 | 站主同意将项目已经使用的 pytest 和导播 TypeScript 编译器声明为测试依赖，并对齐本地/CI 命令。Python 网站运行栈不新增依赖；不因本地验证运行发布脚本。 |
| 后台作业不依赖页面访问 | 原本开发入口只跑 A2S，不自动办理报名截止。现在开发服务器和独立 worker 运行同一组任务；生产 Web 导入不会重复起线程。各场网络轮询结束后才为其现场字段短暂写库，不在等下一台服务器时占写事务。 |
