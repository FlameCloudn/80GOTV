# 后端安全与账号内容审查

## 结论

本轮审查围绕账号权限、论坛和评论、新闻、通知、上传，以及三种猜题游戏展开。确认并修复了管理员旧会话、跳转地址、CSRF 日志、资料同步回滚、反馈隐私与长度、分页边界、新闻评论数缓存、游戏并发提交和异常选手编号等问题。所有改动只在 `backend_refactor_20261026` 隔离目录内，没有读取或修改正式数据库，没有部署。

## 问题和修复

1. 管理员会话只看浏览器里是否留有管理员编号，账号删除后旧会话仍可能被当作管理员。新增 `validate_admin_session()` 查询管理员记录、清理失效会话，并在同一请求内复用查询；数据库故障时拒绝继续处理，不把“查不出来”当成“有权限”。共享入口 `web_app.py` 的全站检查由主审查者接入。
2. 登录后返回地址和 CSRF 失败后的返回地址可能被外部或特殊格式地址利用。`safe_redirect_target()` 现在拒绝跨站主机、反斜杠、重复斜杠和格式错误地址。CSRF 检查覆盖 `PATCH`，JSON/API 请求会收到 JSON 错误。
3. CSRF 失败调试日志原样写入 Referer；Referer 查询部分可能含临时凭据。日志现在只保留请求路径和表单字段名，不保留 Referer 或字段内容。
4. 用户更新群昵称时，网站账号写入成功后，关联选手记录若写入失败，可能留下两边不一致。两次写入现改为同一事务，失败时一起回滚并只提示稍后重试。
5. 意见反馈可提交过长联系方式和页面地址，且完整页面地址会保存查询参数和片段。现在限制字段长度、只保存站内路径并拒绝不安全格式；原页面中的查询参数和片段不进入反馈表。
6. 新闻和论坛页码接受负数或极大数字，可能造成错误页码、错误楼层或数据库异常。列表和回复页现在把页码限制在有效范围内；同一时间的回复增加编号排序作为稳定的先后依据。
7. 新闻 `comment_count` 缓存若为 `NULL`，旧的加减写法会继续得到 `NULL`。新增和删除评论时，评论写入/删除、缓存更新都在同一事务中，并按当前评论数重新计算；新闻列表和详情读取真实评论数，以独立的 `actual_comment_count` 别名避免被新闻原字段遮住。没有批量改写旧数据。
8. 每日猜选手、地图点位和 Bingo 的两个同时到达的提交都可能依据同一份旧进度写入，撞到数据库唯一限制后返回服务器错误。提交现在先取得写入锁，再读取最新进度；已经被另一请求占用的格子或已结束的局会按正常错误处理。新的练习题也先串行处理。
9. 游戏接口把过大的数字编号交给 SQLite 时会报服务器错误；部分非 ASCII 数字也可能在转换时异常。现在只接受合理范围内的正整数，并拒绝不是对象格式的联机猜题 JSON。

## 其他检查

- 通知读取、已读、未读数都按当前用户编号筛选；通知文字由前端写入 `textContent`，没有把通知内容直接作为 HTML 插入。
- 队标和头像上传路径检查扩展名、图片签名、文件大小，并调用图片解码校验；队标保存使用新文件名，原图备份不会覆盖已有备份。后台表单的整个请求体限制由主审查者在共享入口负责。
- 游戏题目状态按用户和游戏记录隔离。联机房间只允许房间成员查看；进行中不发答案，只返回请求者自己的猜测详情和对手次数。测试覆盖三种日常游戏的不同账号进度，以及联机房间内外的回答范围。
- `routes/notifications.py` 和 `services/notification_service.py` 未发现需要修改的问题。审查结论来自代码和隔离测试，不代表对所有生产数据、浏览器组合或游戏规则做了形式化证明。

## 测试证据

- 先加反例再修复：触发器模拟关联选手写入失败，确认群昵称不会只写入账号一侧。
- CSRF 日志测试在修复前能从记录参数里找到 Referer 查询值；移除 Referer 后通过。
- 新闻评论数测试先把缓存设为 `NULL` 并保留两条评论；旧逻辑无法显示和恢复正确计数，改后网页显示真实数量，新增后缓存为 3，删除后恢复为 2。
- 三种游戏并发反例在修复前出现重复序号/格子并返回 500；写入锁和重读状态后两次请求均以正常结果结束，记录没有超出规则。
- 超范围编号、非 ASCII 数字和错误形状的 JSON 测试在修复后均被正常拒绝，没有服务器错误。
- 新增测试文件：`tests/test_refactor_account_security.py`、`tests/test_refactor_content_security.py`、`tests/test_refactor_games_security.py`。它们也覆盖失效管理员会话、跳转边界、负数/超大页码、反馈隐私、跨用户状态隔离和未结束联机答案隐藏。
- 最后合并运行了 13 个相关测试模块，共 124 项全部通过；包含账号/权限、论坛、通知、上传、后台、原有猜题游戏和新增回归测试。

## 范围与未确认项

检查范围包括 `routes/auth.py`、`routes/forum.py`、`routes/comments.py`、`routes/news.py`、`routes/notifications.py`、`routes/feedback.py`，通知和队标服务、后台账号/目录/新闻/运营蓝图、数据库/网页辅助函数，以及猜选手、地图点位、选手 Bingo 服务和路由。共享 `web_app.py`、`models.py` 由主审查者维护；没有在本报告中把其改动归为本模块所有。

本轮只做后端行为和返回页面内容的本地检查，没有进行公网部署、生产数据库测试或截图验收。历史 `news.comment_count` 为 `NULL` 的记录没有被批量更改；网页会显示真实数量，某条新闻发生下一次评论增删时该条缓存才会重算。游戏题库内容和各项计分规则依照现有代码，没有独立核实是否符合产品设想。
