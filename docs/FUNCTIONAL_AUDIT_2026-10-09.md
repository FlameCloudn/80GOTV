## 已确认并修复

### 1. 账号审核查询失败后放行受限操作

- 位置：`web_app.py::_require_site_login()`；反馈等路由依赖这里检查审核状态。
- 触发：浏览器保留 `user_id`，查询账号审核状态时数据库发生异常。
- 原因和影响：原来异常分支返回 `None`，意味着继续执行路由，并不意味着拒绝。反馈提交没有第二次审核检查，论坛和私有读取也可越过这道检查。
- 修复：保留登录，但受限操作返回 503 和明确的重试提示；仅明确公开的只读入口继续。私有读取也不能因使用 GET 而默认通过。
- 证据：`tests/test_account_authorization.py` 模拟的是审核查询故障，不模拟保存成功。检查拒绝时没有写入、登录仍在、恢复后只保存一条；公开页面和公开接口不受这次权限检查故障误伤。

### 2. 旧登录状态绕过资料补全

- 位置：同一请求前检查中的 `needs_completion` 分支。
- 触发：账号在数据库中缺失应填的学校状态或校内群昵称，但浏览器保留旧的“资料已完成”登录状态。
- 原因和影响：原来只会清除补全标记，不会根据当前缺失资料重新设置标记，受保护操作可能继续。
- 修复：每次依据数据库资料设置或清除标记。
- 证据：新增测试修改真实数据库资料，保留原会话，确认反馈被拒绝且数据库无新增记录。旧测试中手工制造的未完成账号已补齐真实资料，不是放宽权限断言。

### 3. 手机反馈入口不可用，浏览器测试绕过入口

- 位置：旧 CSS 隐藏手机 `#fbBtn`；`tests/e2e/frontend-smoke.spec.js` 的手机分支直接调用 `showModal()`。
- 触发：手机宽度访问反馈功能。
- 原因和影响：弹窗组件能打开，真实用户却看不到入口；测试人为打开弹窗掩盖了断掉的操作流程。
- 修复：在当前样式文件 `static/css/hltv_refresh.css` 恢复入口显示；端到端测试统一实际点击，不再直接打开反馈弹窗。
- 证据：修复前真实点击测试失败；现在验证入口可见、可点击、弹窗显示、填写、真实提交、精确保存字段、管理员列表可见和关闭后的焦点。另有失败后保留草稿、恢复按钮、再次真实提交只保存一条的测试。
- 边界：浏览器登录使用测试账号会话，不代表浏览器已走过真实 Steam、邮箱和图片验证码。
- 用于读取保存记录的 `/__e2e__/feedback-records` 只在专用测试服务注册，正式网站启动不注册。它读取实际数据库，不返回预设的成功数据。

### 4. 非法反馈数据导致报错或被静默改写

- 位置：`routes/feedback.py::feedback_submit()`。
- 触发：请求正文为数组，或内容、联系方式等字段不是文本。
- 原因和影响：原来默认把正文当字典、字段当文本，可能 500；空数组联系方式还可能被当成空文本而保存成功。
- 修复：在保存前验证正文和文本字段，返回 400，不写入。
- 证据：新增非法数据测试检查响应和记录数。另有真实 SQLite 写入后、提交失败的测试，证明没有残留记录，重试只保存一条。数据库保存失败原本已有错误返回，这部分不是新发现的“伪成功”。

### 5. 未匹配地图落到错误槽位，可能覆盖其他图

- 位置：`utils/demo_parser.py::match_map_slot()`、`services/demo_service.py::analyze_demo()` 和 `import_demo_data()`。
- 触发：导入的 Demo 地图不在本场地图中，或确认时选择了与 Demo 不同的地图槽位。
- 原因和影响：未匹配时默认第一槽或空槽，随后用那个槽位保存比分和统计。
- 修复：未匹配明确返回无效结果；分析和确认两步均拒绝不一致地图，不再猜位置。
- 证据：未知地图、空槽、手工改错槽位、正常标准化名称测试；失败前后的完整统计和比分快照相同。

### 6. 保存失败仍给出预览，还可能替换旧录像

- 位置：`blueprints/admin_matches.py::admin_import_demo()` 分析步骤。
- 触发：解析成功，但复制录像或提交数据库失败。
- 原因和影响：原来先把预览加入成功列表，之后才保存文件；用户可能看到可以确认导入的预览，但录像并未保存成功。另一个独立错误是直接覆盖同名旧录像，后续数据库提交失败只能撤回数据库，不能恢复被覆盖的文件。
- 修复：文件和数据库保存成功后才加入预览，失败撤回数据库写入；新上传使用独立文件名，提交成功才更新比赛引用，不覆盖或删除旧录像。
- 证据：外部解析器在此故障测试中模拟；文件保存故障、路由处理、预览生成和数据库核对是真实执行。保存失败不出现确认导入按钮、不保存录像引用。另有真实解析器正常流程检查。
- 文件保护测试使用真实复制写入，随后制造数据库提交失败。修复前旧文件内容已变成新上传内容；修复后旧文件字节和数据库引用均不变，没有确认导入按钮。
- 边界：不自动删除旧版本或失败的新副本，磁盘占用可能增加。本次没有擅自清理用户文件。

### 7. 批量导入一半失败仍提交并报完成

- 位置：同一路由的 `import_all` 分支。
- 触发：第一份成功、后一份无效，或空列表。
- 原因和影响：原来忽略失败返回值并继续提交，可能替换部分旧数据；空列表也报批量完成。
- 修复：任一份失败，整批撤回；非空有效数据才接受。完成提示在真正提交后生成。
- 证据：通过真实导入入口，先处理有效地图再处理失败地图；核对整份原始记录和比赛字段未变、没有成功提示。空批次明确失败。

### 8. 创建选手的数据库失败被吞掉，少导入人仍报成功

- 位置：`services/demo_service.py::auto_create_user_from_demo()` 和 `import_demo_data()`。
- 触发：Demo 有未见过的选手，创建账号遇到非重名的写入错误。
- 原因和影响：把多种数据库异常当重名重试或返回空结果；上层跳过该选手继续保存，并废弃原版本。
- 修复：仅用户名确实重名时选择新名字；其他写入错误立即失败，并由整个导入撤回。不能识别或创建的人不能静默跳过。
- 证据：真实 SQLite 触发器拒绝新账号写入，修复前少人统计仍保存，修复后原快照不变且明确失败。另测真正的用户名重名仍能导入，防止误伤合法场景；该测试不连接 Steam 资料接口。

### 9. 同队超过五人被静默截掉

- 位置：`import_demo_data()` 两处排序后 `[:5]`。
- 触发：一队有六名以上不同选手，例如含替补的录像。
- 原因和影响：按评分取前五名，其余不导入，却仍表现为正常完成。
- 修复：不假装已经支持替补统计。当前明确拒绝这种录像，不改变原数据；README 同步说明能力边界。
- 证据：真实数据库六人输入测试修复前失败、修复后不发生任何统计或比分变化。

### 10. Demo 下载入口缺少登录限制

- 位置：`routes/match_assets.py::download_demo()`。
- 触发：匿名访问比赛的下载路由。
- 原因和影响：直接静态 Demo 已被阻止，但下载路由未检查登录，仍可取得文件。
- 修复：下载要求用户账号或管理员身份；普通账号仍接受前面的审核检查。保留管理员单独登录，不要求再关联普通用户账号。
- 证据：使用真实测试文件，匿名被引导登录，管理员下载获得原始文件字节。没有移动或修改原 Demo。

### 11. 过期开赛时间让比赛自动结束，状态规则不一致

- 位置：`utils/match_utils.py` 状态查询片段、`services/match_service.py::supplement_temp_teams()`。
- 触发：比赛开赛时间超过一天但管理员没有结束；或显式 live 但没有开赛时间。
- 原因和影响：SQL 把超过一天的比赛判完成，违背 README“只有管理员手动结束”；另一条页面路径忽略显式 live，显示不一致。
- 修复：仅显式 completed 才算结束；过期但未结束的比赛保持直播；尊重显式 live。
- 证据：对照列表筛选、页面计算和管理员结束的测试。旧测试把超过一天自动结束写成预期，已根据明确业务承诺纠正，并非为迁就实现而放宽断言。

### 12. 预测在比赛中途结算，重新开启后又保留旧积分

- 位置：`services/match_service.py::score_predictions()`、后台 `admin_match_reopen()`。
- 触发：直播已有不相等比分，用户读取预测页；或管理员误结束、重新开启后结果改变。
- 原因和影响：结算查询不要求 completed；重新开启也没有撤回结算。临时结果会永久污染预测积分。
- 修复：显式完成后才能结算；重新开启时同一笔数据库保存撤回本场积分和结算标记。
- 证据：真实投票入口保存 2:1 预测，直播读取页面及接口均不结算；结束后为 8 分且重复结束不重复加分。重新开启清零，结果改为 1:2 后再次结束为 0 分，而不是旧的 8 分。
- 边界：测试比分由测试数据设置，验证的是预测与状态规则，不假装该测试已经连接真实 CS2。

### 13. 换图串用上一张图的状态与历史事件

- 位置：`routes/live_ingest.py::_save_gsi_payload()`、`routes/live.py` 当前图日志筛选。
- 触发：上一张图下包、存有阵亡位置后切图，新图首帧继续下包或健康值变化。
- 原因和影响：只清理部分数组，仍拿上一图的 GSI 作比较，可能制造阵亡或漏掉下包；数据库历史日志兜底又会把旧图事件放回当前视图。
- 修复：换图首帧不与上一图比较；当前图视图只取当前地图事件，历史记录不删除。
- 证据：新图无虚构阵亡，第一回合下包正常记录；当前视图无旧图事件，但数据库仍保留两张图日志。本次还补了断线后换图的组合测试，修正过期帧清理和地图判断顺序，防止修复之间互相抵消。

### 14. 导播重启或重新同步导致连接永久被拒绝

- 位置：接收 GSI 的连接检查；`jts-hud-manager/src/main/server/integrations/80gotv.ts::resetForwardTarget()`。
- 触发：同场比赛重新同步生成新连接编号，或导播重启；数据库仍保留旧编号。
- 原因和影响：网站无期限拒绝不同编号，正常重连也无法恢复；同场重新同步又无必要地换编号和清零帧序号。
- 修复：同场重新同步保留编号和序号；旧连接已过现有 45 秒有效期才允许新连接接管，不跨连接比较帧序号；仍在使用的连接不能被随便抢占。
- 证据：当前连接冲突拒绝、过期后新连接接受、旧连接回流拒绝；重复帧不写入、旧帧拒绝、新帧可保存。Node 测试读取并编译生产中的实际重置函数，不复制一份测试实现。
- 边界：Node 测试提供函数周围的状态，不启动完整 Electron、CS2 或 OBS。
- 直播接口测试为了连续发送故障样本而模拟了频率限制，保留真实推送鉴权、连接检查、存储和读取；不能据此证明生产频率限制和网络重连体验。

### 15. 已结束或取消的比赛仍可被推送覆盖

- 位置：`routes/live_ingest.py` 的 GSI、GOTV 和地图结算入口。
- 触发：比赛取消后继续发帧，或管理员结束后导播再送一份新地图结果。
- 原因和影响：部分分支只处理 completed，地图结算还缺少结束保护，违背“结束后停止接收覆盖”。
- 修复：结束或取消后拒绝新覆盖；对于结束前已经保存过的相同地图结果，保留无写入的重复确认，避免正常重试无故失败。
- 证据：取消后不创建直播记录；结束后新结果拒绝且原数据不变；已保存结果重试仍返回重复确认。

### 16. 英文模式存在未翻译后台提示和错误替换

- 位置：`static/js/i18n.js`。
- 触发：英文模式打开新增后台控制，或含图标的地图标签。
- 原因和影响：新文案漏入字典，通用部分替换先执行还破坏完整短语，原有严格浏览器检查失败。
- 修复：按现有翻译机制补齐实际界面文案，并优先处理完整短语；未隐藏文字或放宽浏览器断言。
- 证据：原浏览器英文模式检查已重新通过。不能据此认定这些文案就是所有旧 GitHub 邮件的原因。
