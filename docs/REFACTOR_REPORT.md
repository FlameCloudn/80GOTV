## 2. 现在的模块分工

保留 Flask + SQLite，没有引入额外服务器、分布式组件或第二套 Demo 解析器。

| 位置 | 负责什么 |
| --- | --- |
| `web_app.py`、`config.py` | 配置只从本副本读取；统一限制请求大小、校验账号身份、返回错误和关闭本次请求打开的数据库连接。 |
| `routes/`、`blueprints/` | 接收网页表单和接口请求，检查权限，调用业务函数并向前端返回结果。原页面和地址保留。 |
| `services/match_service.py`、`bracket_service.py` | 比分是否合法、能否结束比赛、晋级关系、历史改分后如何同步、预测积分。 |
| `utils/bp_manager.py` | BP 步骤、轮到哪一方、名单和口令的有效性、多人同时操作时的状态保护。 |
| `services/live_service.py`、`routes/live_ingest.py` | 校验 GSI/GOTV/导播数据，区分进行中的地图与已确认结算，处理重发和异常回退。 |
| `utils/stats_calc.py`、`performance_service.py` | 评分估算、按有效回合加权、原始统计与生涯汇总的一致性。 |
| `services/demo_service.py`、`utils/demo_parser.py` | 解析、预览、匹配历史阵容、导入新版本、保存扩展事件和同步比分。 |
| `services/public_data_service.py`、`home_service.py` | 集中处理公开列表、筛选、分页、战队/地图统计和首页共用查询，避免路由各算一套。 |
| `utils/stats_display.py` | 统一区分未知值与真实 0，统一海报所用的历史队伍侧别与数值文本。 |
| `models.py` | 保留既有建表和兼容升级方式；当前结果去重后刷新对应汇总，请求结束时释放遗留连接。 |

写入仍由现有业务入口负责一次性提交。比分、晋级、预测积分、统计版本等相互关联的更新，任何一步失败都回退，不留下只改一半的数据。

没有为了满足架构名词而改成 Application Factory（每次通过工厂函数创建应用），也没有把每条 SQL 再包进一层 Repository。现有路由依赖共享应用对象，全面转换会扩大改动面。本次将复杂规则集中到服务函数，并用真实流程测试约束行为，而不是只搬文件。

## 4. Impact 核对结论

不能把本次公式称为 HLTV 官方精确算法。[HLTV 2.0 原说明](https://www.hltv.org/news/20695/introducing-rating-20)和 [2.1 说明](https://www.hltv.org/news/40051/introducing-rating-21)没有公开完整可复现公式。

本站继续保持 Rating 2.0 的现有产品约定。新 Demo 和直播采用 [CS Demo Analyzer 的实现](https://github.com/akiver/cs-demo-analyzer/blob/main/pkg/api/player.go)所使用的[公开回归近似](https://dave.xn--tckwe/posts/reverse-engineering-hltv-rating/)：

```text
Impact ≈ 2.13 × 每回合击杀 + 0.42 × 每回合助攻 - 0.41
```

Rating 近似的常数项修正为 `0.1587`，去掉没有来源的 3 分上限。缺必要输入时返回未知，不造评分；来源标记为 `csda_hltv2_regression_v1`、`official_hltv_formula=false`。

真实验证：只读解析两份原 Demo，共 10 名选手、39 回合、20 条选手地图记录。新计算与 CSDA 对应输入对照，Rating 四舍五入到两位后的不一致数为 0。临时库重复导入第二图后为 20 条有效行、10 条旧历史行、版本 2，旧行原始指标保持不变。

**没有批量重算真实历史。** 旧 Impact 可能仍是原自定义口径，新记录是上述估算；现有全时段平均可能混有旧口径。必须在用户确认后才能从原 Demo 重导或另做口径迁移，不能凭数值猜来源。

新增扩展解析保留回合、击杀、伤害、经济、购买、炸弹、闪光/致盲、HE、烟雾事件及完整性标记。文件追加保存，不覆盖原 Demo。分边事件不完整时明确保留未知，没有凭空补出分边 KAST/ADR 或 WPA。

### 首轮保留的界面问题

390px 手机宽度下，原后台导航展开后覆盖比赛编辑页的状态按钮，队伍区域也有横向挤出。自动点击被真实页面遮挡，不能完成手机后台结束比赛流程。桌面同流程通过；公共首页和选手页另做手机验证。

### 其他边界
